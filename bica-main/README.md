# BICA Illusions — ReflectiveVLM v0.3

Исследовательский Python-проект для изучения **двойных визуальных образов** с использованием VLM, независимой саморефлексии и адаптивной проверки признаков.

**Цель:** проверить, повышает ли дополнительная визуальная проверка качество *обоснованного* обнаружения альтернативного образа без роста ложных находок на обычных изображениях.

> **Статус (18.11.2026):** прототип v0.3 и тесты готовы, но **его превосходство над baseline пока не доказано**. Реальные результаты v0.2/v0.2.1 использовались для технической отладки. Полноценное сравнение по утверждённым эталонам и слепым человеческим оценкам ещё впереди.

## Состав проекта

- `illusion_agent/` — ядро эксперимента, промпты, клиенты, режимы и диагностика.
- `illusion_agent/reflection.py` — выбор визуальных областей и политика запуска дополнительной проверки.
- `tools/` — подготовка манифестов, наборов и форм разметки.
- `data/ambibench_debug/` — манифест и **предварительные, ещё не утверждённые** эталоны шести примеров.
- `notebooks/BICA_v030_Colab_FULL.ipynb` — автономный Colab-ноутбук для GPU-инференса с Qwen2.5-VL-3B.
- `tests/` — автоматические тесты, работающие без GPU.
- `docs/08_v030_protocol_ru.md` — текущая методика исследования.

**Основные режимы:** `direct`, `repeat`, `hypotheses`, `evidence`, `reflect`, `reflect_zoom`, `reflect_adaptive`.

В режиме `reflect_adaptive` выполняются первоначальный анализ, независимое чтение без истории и подсказки, **необязательный** визуальный challenge и итоговый арбитраж. Триггеры challenge основаны на диагностике ответов, а не на эталонах. Это не гарантирует визуальную истинность.

## Установка локально (Windows PowerShell)

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e . "Pillow>=11,<13"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Python 3.11+; GPU для тестов и `--provider mock` не требуется. Если на компьютере нет Python 3.11, замените `py -3.11` на доступную версию Python 3.11+.

## Данные для пробного запуска

Изображения не включены в GitHub ZIP, поскольку лицензирование исходных репродукций необходимо проверять отдельно. Получение исходных изображений из закреплённой ревизии AmbiBench с проверкой SHA-256:

```powershell
.\.venv\Scripts\python.exe tools\restore_debug_images.py
```

Источник и хеши: `data/ambibench_debug/provenance.json`. Загрузчик не меняет эталонную разметку. Эти шесть изображений предназначены **только для отладки**, не для независимого финального теста.

После загрузки проверить план без обращения к VLM:

```powershell
.\.venv\Scripts\python.exe -m illusion_agent run --manifest data/ambibench_debug/manifest.jsonl --modes direct,reflect,reflect_adaptive --max-calls 70 --dry-run
```

Синтетический тест (не считать качеством распознавания):

```powershell
.\.venv\Scripts\python.exe -m illusion_agent run --manifest data/ambibench_debug/manifest.jsonl --modes direct --provider mock --max-calls 12 --output runs/smoke_mock
```

## Запуск на GPU в Google Colab

Откройте `notebooks/BICA_v030_Colab_FULL.ipynb` на [colab.research.google.com](https://colab.research.google.com/) и выберите **Python 3 → T4 GPU**. Выполняйте ячейки по порядку; после установки пакетов перезапустите сеанс, если ноутбук запросит это. Встроенный ноутбук включает код и отладочные данные для автономного запуска. 

**Не загружайте `runs/`, API-ключи, личные данные и результаты с неанонимизированными оценщиками в публичный репозиторий.** В `.gitignore` предусмотрены основные исключения.

## Научный протокол

1. Независимо разметить изображения двумя людьми; отметить конкретные визуальные признаки каждой интерпретации.
2. Согласовать эталоны и подготовить однозначные контроли.
3. Сформировать независимые подсказки A–D без утечки эталонной метки.
4. Выполнить парное сравнение `direct`, `reflect`, `reflect_adaptive` на одних и тех же изображениях.
5. Слепо оценить наличие двух разных, **визуально обоснованных** интерпретаций; отдельно — ложные альтернативы и затраты вызовов.
6. Публиковать вывод о выигрыше только после оценки качества и неопределённости.

Подробности: [протокол v0.3](docs/08_v030_protocol_ru.md). История предыдущей версии: [README previous](docs/README_previous.md).
