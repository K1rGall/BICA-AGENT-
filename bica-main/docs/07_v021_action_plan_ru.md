# BICA v0.2.1 — план следующего эксперимента

**Точка отсчёта:** исходный настоящий запуск v0.2 от 18.11.2026: 6 изображений × 6 режимов = 36 случаев, 33 `ok`, 3 ошибки схемы. В `review/ratings.csv` нет человеческих оценок. **Не переименовывать этот запуск в v0.2.1 и не перезаписывать его.**

## Изменения в исходном коде

- `core.py`: один строго ограниченный дополнительный вызов `schema_repair` на случай при невалидном JSON. Модель получает свой невалидный текст и конкретную ошибку, а не эталон. Первичный ответ сохраняется в trace. Повторная ошибка остаётся технической ошибкой.
- `reflection.py`: предупреждения о лексическом пересечении кандидатов. Это эвристика, а не судья и не автоматическая коррекция меток. Не позволяет утверждать, что два визуальных образа эквивалентны.
- `colab.py`: дополнительный вызов учитывается в `attempted_calls` и ограничивается `max_calls`. Версия схемы конфигурации изменена — используйте НОВУЮ папку результата.
- `prompts/*.txt`: чётко различаются две интерпретации одной фигуры и несколько характеристик одной фигуры.
- `core.load_manifest`: для четырёх уровней A–D поддержан необязательный тип подсказки `kind=instruction|hypothesis`, не содержащий сведений об истинности. A/B/C — инструкции, D — предложенная гипотеза.
- `diagnostics`: отдельно фиксируются число ошибок схемы, успешных/неуспешных восстановлений и предупреждений.

## Что запустить в Google Colab прямо сейчас

1. Загрузите `BICA_v0.2.1_Colab_FULL.ipynb`, выберите T4 GPU.
2. Если требуется, установите версии библиотек и **перезапустите сеанс**, затем переходите к проверке зависимостей.
3. Загрузите Qwen2.5-VL-3B той же ревизии, что использовалась в v0.2: `66285546d2b821cf421d4f5eb2576359d3770cd3`.
4. Сначала выполните регрессионный прогон на двух изображениях (`ambi-debug-004`, `ambi-debug-005`) и только режимах `reflect`, `reflect_zoom`: четыре случая, 12 основных вызовов + до четырёх восстановлений.
5. Откройте таблицу `schema_failures`, `repair_successes`, `overlap_warnings` и прочтите финальные ответы. Нулевое число технических ошибок **не гарантирует** содержательной правильности.
6. Когда короткий прогон устраивает по стабильности, включите отдельно полный пилот v0.2.1. Он сохраняется в **другую** папку, не поверх v0.2.

## Проверка качества двумя людьми

1. Дайте двум участникам независимые `GOLD_reviewer_A.csv` / `GOLD_reviewer_B.csv` и только изображения. Сначала независимо решите, действительно ли каждый случай двусмысленен.
2. Проверьте `ambi-debug-004`: исходная метка «утка / кролик» может не соответствовать изображению. Решение может быть: `ambiguous`, `ordinary`, `exclude`. Не исправляйте эталон без проверки.
3. Утвердите разметку: две различающиеся трактовки, геометрические опоры для каждой, допустимые синонимы, права/источник. Добавьте обычные контроли, не меняя исходную контрольную группу v0.2.
4. Оцените 36 ответов из исходного v0.2 по `review_id` слепым способом; не раскрывайте режим и исходный эталон до записи оценок. Заполните `both_valid`, `grounded` и для будущих обычных контролей `false_alternative`.
5. Пропущенные/спорные ответы не заполняйте вымышленными баллами; используйте сравнение двух CSV и ручную адъюдикацию.

## Как построить уровни A–D после согласования эталонов

`annotations.jsonl` после согласования должен иметь на каждый пример:
- `review_status = "adjudicated"`;
- `group = "ambiguous"|"ordinary"`;
- `approved_interpretations` = список из 2 разных образов для ambiguous, из 1 образа для ordinary;
- `target_label` = имя второй трактовки для ambiguous, заранее выбранная **ложная** гипотеза для ordinary;
- `cues` = `{ "A":"neutral", "B":"neutral", "C":"neutral", "D":"supported"|"misleading" }`.

Затем выполнить **в корне проекта**:

```bash
python -m tools.build_staged_manifest \
 --manifest data/ambibench_debug/manifest.jsonl \
 --annotations data/ambibench_debug/annotations.jsonl \
 --output data/ambibench_debug/manifest_ABCD_v021.jsonl
```

До завершения ручной разметки команда намеренно отказывает в генерации манифеста, чтобы не превращать неподтверждённые гипотезы в эталон.

## Добавление обычного контроля

После получения изображения из разрешённого источника и подтверждения возможности использования:

```bash
python -m tools.add_ordinary_control \
 --image /path/to/ordinary_photo.png --id ordinary-001 \
 --source "https://example.org/source" --rights "permission/license details"
```

Команда только добавляет кандидат в debug-датасет и помечает его `pending_two_human_reviewers`, **не утверждает**, что изображение действительно однозначно.

## Что НЕ утверждать на защите

- «Процент правильных ответов 33/36»: это процент технически завершённых случаев.
- «Саморефлексия улучшила распознавание»: пока нет проверенной парной оценки.
- «Найдено две фигуры» по `duck in grass` и `bird in grass`: это может быть один объект.
- «Четыре уровня подсказок уже проверены»: исходная выборка была только с пустым `c0`.
